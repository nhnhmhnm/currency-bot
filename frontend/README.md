# Currency Bot Frontend

React + TypeScript + Vite. Node.js 22.12 이상을 사용한다.

```powershell
cd frontend
npm ci
npm run dev
npm run build
npm test
npm run test:e2e
```

- 개발 서버는 기본적으로 `http://127.0.0.1:5173`에서 실행된다. 포트 사용 중에는 Vite가 다음 포트를 선택한다.
- `/api`는 Spring Boot `http://127.0.0.1:8080`으로 프록시한다. 다른 주소는 `.env.local`의 `BACKEND_URL`로 지정한다.
- 로그인 아이디는 기존 백엔드의 `device` 필드에 대응한다. 회원가입은 GENERAL 유형을 요청한다.
- 토큰은 sessionStorage에 보관한다. 운영 환경은 HTTPS, CSP, 서버가 발급하는 HttpOnly 쿠키 기반 세션 등 별도 보안 검토가 필요하다.
- 배포 시 정적 빌드와 같은 출처의 `/api` 리버스 프록시를 구성한다. Vite 개발 프록시는 빌드 결과에 포함되지 않는다.
- 브라우저 테스트는 설치된 Chrome을 사용하며 API를 모의 응답한다. 실제 DB·Redis·백엔드 연결 검증과 구분한다.

## 환율과 주문

- `GET /api/exchange/rates?currency=USD`: 서울 기준 오늘의 은행별 고시. 상단 USD·JPY 탭으로 통화를 선택하고 체크박스로 전신환 매도율·매입율·매매기준율을 함께 비교한다.
- `GET /api/exchange/summary`: 인증한 사용자의 사용·예약 포함 일일 한도와 지갑 가용 잔액. 15초마다 갱신하며 미조회 값을 0으로 표시하지 않는다.
- 고객 구매는 은행 전신환 매도율(`buy_rate`), 고객 판매는 은행 전신환 매입율(`sell_rate`)이다. 재테크는 별도 `/arbitrage` 경로로 매매기준율 구매·판매를 요청한다.
- 주문 입력 기본값은 통화의 고시 단위(`unit`)를 따른다. 구매는 해당 단위의 최적 고시율을 원 단위로 올림하고, 판매는 고시 단위 그대로 표시한다(USD 1, JPY 100). 유효한 당일 고시가 없으면 `0`이며 사용자가 수정한 금액은 재조회 시 유지된다.
- 은행 선택은 기존 백엔드의 최적 환율 선택에 맡긴다. 미리보기는 최근 고시 기준 5분 범위와 수수료·통화 단위·절사 정책을 반영하되 확정 견적은 아니다.
- 주문은 확인창에서 명시적으로 접수한다. 응답은 체결 완료가 아닌 접수로 표시한다. 네트워크 오류 재시도에는 동일 `Idempotency-Key`를 사용한다.
- 환율 연결 실패·당일 데이터 없음은 그대로 표시한다. 사용자가 선택한 샘플 보기는 명시적으로 표시하고 실제 주문을 막는다. 샘플 값은 시장 환율이 아니다.
- 미국·일본 국기 PNG 출처: [FlagCDN](https://flagcdn.com/). 이미지 파일은 로컬에서 제공한다.

## 실행 범위

실제 회원가입·로그인·주문에는 MySQL, Redis, Spring Boot와 통화·회사 계좌 초기 데이터가 필요하다. 이 화면은 계좌 연결·지갑 충전 기능을 추가하지 않으므로 신규 지갑의 잔액은 별도 기존 API로 준비해야 한다. 외부 은행 실거래나 수익 보장 기능은 아니다. 백엔드 주문 상태 조회 API가 아직 없으므로 완료 상태 추적 화면은 후속 범위다.
