# Commit Convention

이 프로젝트는 Conventional Commits 형식을 기본으로 사용한다.

## Types

- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `refactor`: 동작 변경 없이 코드 구조 개선
- `style`: 포맷팅, 공백, 세미콜론, import 정리 등 동작과 무관한 스타일 변경
- `docs`: 문서 추가 또는 수정
- `test`: 테스트 추가 또는 수정
- `chore`: 빌드, 설정, 패키지 관리, 기타 유지보수 작업
- `perf`: 성능 개선
- `ci`: CI/CD 설정 변경
- `build`: 빌드 시스템 또는 외부 의존성 변경
- `revert`: 이전 커밋 되돌리기

## Subject Rules

- subject는 50자 안팎으로 간결하게 작성한다.
- 영어로 작성할 때는 명령형 현재 시제를 사용한다. 예: `add`, `fix`, `rename`
- 첫 글자는 소문자로 작성한다.
- 마지막에 마침표를 붙이지 않는다.
- 무엇을 바꿨는지보다 왜/어떤 의도로 바꿨는지가 드러나면 더 좋다.

## Recommended Practice

- 한 커밋에는 하나의 목적만 담는다.
- 포맷팅 변경과 기능 변경은 가능하면 분리한다.
- 대규모 rename은 별도 커밋으로 분리한다.
- 테스트나 검증을 했다면 PR 설명에 함께 기록한다.
